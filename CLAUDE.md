# Brief Kit: producer playbook

This repo turns an article plus a voiceover into a short narrated YouTube video (Remotion). You are the **producer**: you make one episode at a time by filling one episode folder with **data and media only**.

**To make an episode, use the `new-episode` skill** (`.claude/skills/new-episode/SKILL.md`). It has the full step-by-step procedure and the asset-sourcing prompts. **To make a music video** from the user's own song (`"format": "music-video"`: the song replaces the voiceover, the lyric sheet the script), **use the `music-video` skill**. **To find video ideas** ("recon"), **use the `recon` skill**: it reads the user's X lists and X trending in their own browser, read-only, and reports a ranked list; posts are leads, never facts. This file holds the rules that apply at every step.

## Hard rules

1. **Never edit `.tsx`, `src/kit/**` or `scripts/**` to make an episode.** If something can't be expressed in `episode.json`, tell the user what's missing; don't patch a component. The only files you write are under `episodes/<slug>/` and `public/episodes/<slug>/`.
2. **Facts come only from the article** (`episodes/<slug>/article.md`), **as corrected by the fact-check** (step 1b of the `new-episode` skill: verify the article's figures on the web before scripting, replace wrong ones with sourced figures, cut what can't be verified, and log every change in `notes.md`). Narration and on-screen text (headlines, stats, stamps, regions, outro) must not go beyond these. If you want added context (a date, a definition, background), flag it to the user and get approval. Record approved additions in `notes.md`. With `youtube.use_video_as_citation: true` (`config.yaml`), a YouTube video found through the **youtube** skill can be a source like an article (listed in `sources`, facts logged in `notes.md`); with `false`, videos are leads only and a non-YouTube source must confirm the fact. **Posts on X** are leads only, unless `config.yaml` has `x_posts.enabled: true`: then a post by an account that speaks officially for the company, agency or military involved, or by someone widely recognized in that field, can be a source for what that person or organization said (attributed in the script, "NVIDIA said…"), never for a neutral fact about the world. Archive it with `npm run xpost` (its `--basis` states why the account counts), cite it in `sources`, and log it in `notes.md`. **Music videos:** the lyrics are the artist's words and aren't fact-checked, but anything the video adds on screen (an explainer's dates and figures, a caption) must be true, sourced in `notes.md` and `sources`, and a lyric's own number is never shown as a current fact.
3. **Licenses: PD, CC0, CC BY or CC BY-SA only** (plus `OWN WORK` for material the user made or owns, e.g. their own music, credited as they specify), and every media file needs a `credits.json` entry. No NC, ND, "editorial use only" or unknown licenses. No Pexels, Pixabay or other "free stock" sites, except in **music videos** when `config.yaml` has `licensing.stock_media: music-video`: then Pixabay, Pexels and Coverr are searched first, only through `npm run stock` (the **stock-media** skill), credited `STOCK`, never the thumbnail, and a clip the site marks as AI gets an on-screen note. If footage isn't of the event described, give that visual a `note` ("FILE FOOTAGE · LVIV, UKRAINE, 2022") and tell the user (not in music videos, which claim no clip shows a specific event; their AI stills still carry their note). Web-page screenshots (`npm run shot`) follow the same rule: the page must be PD, CC0, CC BY or CC BY-SA (Wikipedia text is CC BY-SA), never a commercial news site, and photos or logos on the page need their own license or must be cropped out. Infographics from `npm run infographic` (including illustrated explainers from the **explainer** skill used as b-roll) and sounds from `npm run sfx` are credited `OWN WORK`, and their numbers must come from the script and fact-check. The exceptions are AI-generated media, credited `AI-GENERATED` with their provenance. Stills from `npm run generate` (Z-Image Turbo locally or FLUX 3 via Replicate, per `config.yaml` `image_gen.mode`) are a fallback when licensed footage is missing or a poor stand-in, follow the **generate-image** skill's rules (no real identifiable people, no fake record of a specific event, never a copy of a specific photo), and always carry `"note": "AI-GENERATED ILLUSTRATION"`. Music beds from `npm run compose` (Stable Audio 3, local; the **compose-music** skill) are made when `config.yaml` has `music_gen.enabled: true`: instrumental only, never "in the style of" a named artist or song, credited automatically ("Powered by Stability AI"). **YouTube clips:** CC BY, or PD from a verified US federal agency channel's own footage (with its basis in `notes`), and only through `npm run youtube -- <slug> clip`. The kit draws a `VIDEO · <Channel> / YouTube` tag over them, and they are never the thumbnail. **Press images** are the one opt-in exception to the editorial-use ban: when `config.yaml` has `licensing.press_images: true`, an official image or b-roll clip from the manufacturer's own newsroom or press kit may show the product a segment discusses, when no PD/CC media does. Credit it `"license": "PRESS"`, the company as `author`, the press page as `sourceUrl`. Never retailer listing photos, photographers' or outlets' photos, anything under embargo or marked "do not use", and never as the thumbnail. **Posts on X** shown on screen are the other opt-in exception: with `x_posts.enabled: true`, a cited post can appear as a screenshot made only by `npm run xpost --still` (X's own embed of the post, credited `X POST`), in `images/` only, never the thumbnail. If the post's photo or video isn't the poster's own, use `--no-media`.
4. **`npm run check -- <slug>` must show 0 errors before rendering.** Fix the cause; don't work around it. `render` refuses to start otherwise.
5. **Captions show what was said.** If the recording differs from `voiceover.txt`, update `voiceover.txt` to match the audio (see `heard.txt`) and re-run align. Never the other way round. With local TTS the audio is made from the text, so when it misreads a word, respell that word in `voiceover.txt` for the ear (or change `--seed`) and voice it again until the audio says the script. **Voice check, every project:** once a voiceover (episode or Short, TTS or recorded) is laid out and aligned, run `npm run voice-check -- <slug>`. It scans every pause for harsh stops (a word cut off while still sounding). Look at each HARSH and CHECK item (its snippet and waveform in `work/voice-check/`) and fix every real cut-off by re-voicing or rewording the line, then run it again, before the preview. Log the result in `notes.md`.
6. **Wait for the user** at the three handoffs: script approval, the recorded MP3, and preview approval. When `config.yaml` has `voice.enabled: true`, there is no MP3 handoff: right after script approval, voice it yourself with `npm run voice -- <slug>` and carry on (the user hears it in the preview). When it's `false`, wait for the user's MP3 and don't run `npm run voice`. **Music videos** have no voice step; their three stops are the lyrics differences (`lyrics-diff.txt`), the shot plan, and preview approval.
7. **Preview before every render.** Right before rendering, run `npm run preview -- <slug>` in the background; it opens the user's browser on the episode in Remotion Studio. Wait until they've watched it and approved, stop the preview, ask whether they're on AC power, and only then run `npm run render`.

## Commands (all take the episode slug)

```
npm run new -- <slug> [--format countdown|list|short] [--count N] [--theme threat-brief|clean-light|after-dark|military|military-comparisons|erotic|frontier|blackout]
npm run new -- <slug> --format music-video --song <path> [--title "…"] [--subtitle "…"] [--artist "…"]   # music video (music-video skill)
npm run lyrics -- <slug> [--force] [--aligner mms|whisper]   # music videos: lyrics.txt + song -> timing.json (words, lines, beats), lyrics-diff.txt
npm run voice -- <slug> [--force]         # local TTS (config.yaml voice:): voiceover.txt -> voiceover.mp3, then align
npm run voice-check -- <slug>             # scan the laid-out voiceover for harsh stops (words cut off at pauses); every project
npm run compose -- <slug> bed --prompt "..." [--force]   # local music bed (config.yaml music_gen:, compose-music skill), new random seed each run
npm run short -- <slug> [--count 1-3]     # scaffold YouTube Shorts (<slug>-short1…) from an episode; each is its own small episode
npm run align -- <slug> [--estimate]      # timing.json from voiceover.mp3 (or rough, from text only)
npm run assets -- <slug>                  # assets.json from clips/, images/, library sfx/music
npm run generate -- <slug> <name> --prompt "..." [--detail high]   # last-resort AI still: local Z-Image Turbo or FLUX 3 (config.yaml image_gen:, generate-image skill)
npm run youtube -- <slug> search "<query>" [--limit 10] [--cc]   # YouTube leads (youtube skill); flags go after the positionals
npm run youtube -- <slug> transcript <id|url> [--words 300]   # 300-word preview; full text in raw/youtube/<id>/transcript.txt
npm run youtube -- <slug> clip <id|url> <name> --from <t> --to <t> [--license PD --basis "<…>"]   # CC BY (or federal PD) clip, ≤ 15 s
npm run stock -- <slug> search "<query>" | get <site>:<id> <name> | import <file> <name> --site … --page <url> --author "…"   # music videos only (stock-media skill)
npm run shot -- <slug> <name> --url <url> [--selector "<css>"] [--license PD]   # web-page screenshot still (PD/CC pages only)
npm run xpost -- <slug> <post url> --basis "<why the account counts>" [--still <name>] [--no-media]   # post on X as a source (x_posts.enabled only)
npm run infographic -- <slug> <name> [--still]     # render episodes/<slug>/infographics/<name>.html (see infographic skill)
npm run explainer -- new|storyboard|frames|render <name> [--episode <slug>]   # illustrated explainer (see explainer skill)
npm run sfx -- <slug> <name> --sound <kit sound> | --recipe   # synthesize a new sound into the episode's sfx/ (npm run sfx -- list)
npm run check -- <slug>                   # 0 errors required
npm run preview -- <slug>                 # check, start Studio, open the browser on this episode (run in background); props-panel edits save to episode.json via the canvas button / Ctrl+S
npm run render -- <slug>                  # only after the user approves the preview -> out/<slug>/youtube.mp4
npm run thumb -- <slug>                   # out/<slug>/thumbnail.png
npm run credits -- <slug>                 # out/<slug>/DESCRIPTION.md
npm run kill                              # stop leftover render processes from this repo
```

## How timing works (read before writing episode.json)

- `timing.json` = every word of `voiceover.txt` with its audio time. Everything on screen is placed by **cues**: short spoken phrases from the script, never seconds.
- Cue matching: case- and accent-insensitive, punctuation ignored. All words must match exactly except the last, which may be a prefix ("kiwi" → "kiwifruit"). Pick cues that are distinctive and spoken where the event should happen.
- Search order is strict, and `check` errors if a cue isn't where it should be:
  - Segment `marker`s are found in order through the whole script. The outro `cue` comes after the last marker.
  - Cold-open beat cues and `title.cue` are found in order before the first marker. `title.bigCue` is found inside the title line.
  - Text sections (`"kind": "text"` entries in `segments`) have a `marker` too, found in the same order as the numbered segments; they don't use up a number.
  - Stat cues are found in order inside their segment, after the marker. Visual cues (every visual after the first needs one) are also found in order inside their segment, independently of the stats.
  - Outro line cues are found in order after the outro cue (the first line can omit its cue), then the CTA cue.
- Scenes cut 0.12s before their marker, so the number slam lands on the word.

## Where things are

- **Keep every episode file with the episode, never in a temp or scratchpad folder.** Raw downloads (original clips, stills, logos, sounds) go in `episodes/<slug>/raw/<name>/`, one new folder each, never executed. Working files go in `episodes/<slug>/work/`: contact sheets, test stills and sync clips, explainer drafts, storyboard review pages, logs. Finished media stays in `public/episodes/<slug>/`. Both folders are local-only (gitignored).
- Schema with every field documented: `src/kit/schema.ts`. Each `episode.json` gets autocomplete from `episodes/episode.schema.json`.
- Text limits: `LIMITS` in `scripts/lib/check.ts`, e.g. headline ≤ 6 words, stamp ≤ 16 chars, stat value ≤ 10 chars.
- To add a one-off sound on a spoken cue, use `audio.sfxExtra` (`{ "sfx": "glitch", "cue": "...", "volume": 0.45 }`). To silence one preset sound for an episode, list its event in `audio.sfxOff` (e.g. `["stampBeat"]`; events are `SFX_EVENTS` in `src/kit/schema.ts`).
- Shared sounds and the music bed: `public/library/` (`sfx/`, `music/`, `credits.json`). Available sfx: alarm, glitch, impact, riser, tick, typing, whoosh, whoosh2. Music: bed.
- **A sound the library doesn't have:** synthesize it with `npm run sfx -- <slug> <name> --sound <kit sound>` (one of the ~40 sounds in the explainer sound kit, with options such as `--f`, `--dur`, `--material`) or `--recipe` (layer kit sounds and raw tones and noise in `episodes/<slug>/sfx/<name>.js`). It lands in the episode's `sfx/`, normalized like the library and credited `OWN WORK`, and is used by name in `sfxExtra`. A name that matches a library sound replaces it for that episode. `--library` adds it to `public/library/` for every episode instead.
- Map country names must match world-atlas 110m (e.g. "United States of America", "Dem. Rep. Congo", "Bosnia and Herz."). `check` warns and suggests names.
- **Shorts** (`format: "short"`, vertical 9:16, `config.yaml` `shorts:`): each is its own small episode (`npm run short -- <slug>` from an episode, or `npm run new -- <slug> --format short` standalone), with its own ≤ 60 s script from the parent's facts. The procedure is section 8 of the `new-episode` skill. Shorts turn the on-screen sources and credits rolls off; their sources and credits go in the description (`npm run credits`).
- Every `episode.json` (Shorts too) gets a **`summary`**: 1–2 sentences for the top of the YouTube description, facts from the article and fact-check only. `npm run credits` writes it into `DESCRIPTION.md`, which it regenerates each time, so never edit the summary there by hand.
- Every video ends with a **sources scene** and a **credits roll** (on by default; `outro.sourcesCard` / `outro.creditsCard`). So `sources` in `episode.json` must list what the script relies on, and every media file must be in `credits.json`; the roll is built from it.
- Human docs: `README.md`.
